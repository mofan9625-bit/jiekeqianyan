从早期的 Shadowsocks、VMess 到如今的 Hysteria2 (歇斯底里) 与 TUIC，代理传输协议经历了几代演进。为什么基于 UDP 的新协议能在恶劣网络下实现速度翻倍？本文将深入浅出解析其底层原理。

---

### 一、传统 TCP 协议在弱网下的痛点

传统代理协议大多基于 TCP 传输层协议。在遇到拥堵丢包时，TCP 的重传机制与拥塞控制算法会导致发包速度陡降，造成严重的网络卡顿。

```
TCP模式：发包 ➔ 丢包 ➔ 等待重传 ➔ 触发减速算法 ➔ 网页卡死
```

---

### 二、Hysteria2 与 TUIC 协议的破局之道

Hysteria2 与 TUIC 均基于 **QUIC (UDP)** 协议重构，彻底摆脱了传统 TCP 协议的束缚。

#### 1. Hysteria2 (歇斯底里 2)
* **核心机制**：采用了独特的拥塞控制算法，无论网络是否丢包，均按照设定的最大带宽强行发包。
* **适用场景**：高丢包、高延迟的恶劣公网环境，能在晚高峰时期化腐朽为神奇，跑满本地宽带。

#### 2. TUIC 协议
* **核心机制**：设计初衷旨在降低握手延迟并提高 0-RTT 建立连接的能力，同时拥有优秀的多路复用能力。
* **适用场景**：对连接响应速度敏感的网页浏览与移动端握手场景。

### 三、新旧协议综合对比

| 协议名称 | 传输层基石 | 抗丢包性能 | 握手延迟 | 适用客户端支持 |
| :--- | :--- | :--- | :--- | :--- |
| **Shadowsocks** | TCP | 弱 | 一般 | 100% 全客户端支持 |
| **VMess / Trojan** | TCP | 中等 | 中等 | 全主流客户端支持 |
| **Hysteria2** | QUIC (UDP) | 极强（暴雪级突破） | 极低 | Clash Verge Rev / sing-box |
| **TUIC v5** | QUIC (UDP) | 极强 | 极低 (0-RTT) | sing-box / Stash |

在每一个追求极致网络体验的极客家庭里，单机运行代理客户端往往是临时妥协的产物：每买一台新手机、平板、电脑都要重复下载软件、导入订阅；家里的任天堂 Switch、PS5 联机加速繁琐不堪；更不用说电视盒子上反人类的遥控器输入了。

**软路由透明网关（Transparent Proxy Gateway）是终结这一切混乱的终极解法。**

通过一台低功耗的小主机（如 J4125、N100 或工控机）刷入 **OpenWrt** 或专为小白优化的 **iStoreOS**，在局域网入口层接管流量，全屋所有连接 Wi-Fi 的设备无需安装任何 App，开机即享丝滑的国际互联网加速。本文将手把手带你理清**主旁路由拓扑架构**，规避致命的**网关死循环**与**DNS 泄漏**问题。

### 一、 为什么极客家庭必须有一台透明网关？

```
【传统单机代理模式】
用户设备 (PC/手机/电视) ──> 分别运行 Clash/小火箭 (耗电/多配置/偶发断连) ──> 路由器 ──> 公网

【软路由透明网关模式】
全屋设备 (全平台/无需App) ──> [软路由透明代理网关] (统一规则分流/DNS过滤) ──> [IEPL物理专线] ──> 秒开全球
```

1. **多终端零学习成本**：家里长辈、访客接入 Wi-Fi，无需任何配置，海外文献、学术网站秒开；
2. **解锁受限设备加速**：PS5、Xbox 外服联机、HomePod、Kindle、Tesla 车机更新以及智能家居等根本无法安装第三方 App 的设备，瞬间具备全球加速能力；
3. **分流算力外包**：复杂的分流规则匹配与加密解密由软路由的 x86 CPU 统一计算，释放手机和轻薄本的电池寿命与性能开销。

### 二、 主路由与旁路由网络拓扑避坑图解（拒绝死循环）

许多新手在配置旁路由时，经常遇到“全屋断网”、“微信收不到消息”或“网页加载极慢”，90% 的原因出在**网络拓扑与网关互指配置错误**上。

```
                       ┌──────────────────────┐
                       │   光猫 (Bridge 桥接)  │
                       └──────────┬───────────┘
                                  │
                       ┌──────────▼───────────┐
                       │   硬路由 (主路由 PPPoE)│  192.168.1.1 (负责拨号与全屋 Wi-Fi)
                       │   DHCP 网关指向旁路由  │
                       └──────┬────────┬──────┘
                              │        │
             ┌────────────────┘        └────────────────┐
             ▼                                          ▼
┌───────────────────────────┐              ┌───────────────────────────┐
│     软路由 (旁路由网关)     │              │        家庭终端设备       │
│      192.168.1.2          │              │  (手机 / 电脑 / 电视盒子)  │
│  运行 OpenClash / PassWall│              │  自动获取 IP: 192.168.1.x │
│  网关指向主路由 192.168.1.1 │              │  默认网关: 192.168.1.2    │
└───────────────────────────┘              └───────────────────────────┘
```

#### 关键三步配置法则：
1. **IP 处于同网段**：假设硬路由（主路由）IP 为 `192.168.1.1`，软路由后台静态 IP 必须设置为同网段（如 `192.168.1.2`），子网掩码统一为 `255.255.255.0`。
2. **软路由的网关指向主路由**：软路由的“IPv4 网关”必须填入主路由 IP（`192.168.1.1`），DNS 同样填入主路由 IP 或公共 DNS。**如果配错成指向自己，会引发致命死循环！**
3. **关闭软路由的 DHCP 服务**：全屋网络只保留主路由一个 DHCP 服务器。在主路由的 DHCP 设置中，将“默认网关（Gateway）”和“主 DNS”指定为旁路由的 IP（`192.168.1.2`）。

遇到无法正常连接或订阅报错时，可以按照经典排错手册逐步排查：[《为什么你的代理经常断连？节点超时、订阅更新失败的 6 种排查方法》](/2026/10/05/node-timeout-troubleshooting/)。

### 三、 OpenClash / PassWall 核心调优实战

在 iStoreOS 或 OpenWrt 的应用商店中，**OpenClash** 是功能最为完善的插件。在配置时，请重点调整以下三个核心开关：

#### 1. 运行模式选型：Fake-IP vs Redir-Host
- **强烈推荐 Fake-IP 混合模式（TUN + 混合）**：客户端发起域名解析时，软路由内核直接返回一个虚构的内网 IP（如 `198.18.0.x`），真正的 DNS 查询由代理服务端在海外机房代为完成。**这种模式下完全免疫国内运营商的 DNS 投毒与污染**，首包响应速度极快。
- **兼容模式 Redir-Host**：仅在局域网内有老旧特种工业设备对 Fake-IP 不兼容时才启用。

#### 2. 避免 IPv6 导致的旁路泄漏
国内三大运营商普遍开通了 IPv6。若主路由分配了公网 IPv6 地址，许多海外 App（如 YouTube、Twitter）会优先走 IPv6 绕过旁路由，导致代理失效或 IP 泄漏。
* **极客解法**：在 OpenClash 设置中勾选 **“禁止 IPv6 解析（Filter AAAA）”**，强制海外流量全部回退至 IPv4 虚拟网卡由规则调度接管。

### 四、 全屋大并发下的机场节点与协议选型

一台软路由接管了全屋数十台设备，其并发连接数（TCP Sockets）瞬间可达数千。这要求底层代理节点必须具备极强的抗并发与大吞吐能力：

1. **不限设备并发与 1.0x 真实倍率**：市面上很多廉价机场限制“最多 3 台并发在线”，在软路由环境下分分钟触发后端熔断封禁。务必挑选支持不限并发、真 1x 计费的企业级专线服务商（如站内推荐的闪电鼠、云界线等）。
2. **协议选择与 UDP 承载能力**：软路由硬件普遍性能充裕，建议主力选择 **Shadowsocks-2022** 获得最低的 CPU 占用与零抖动；备用节点选用 **Hysteria 2** 应对弱网丢包。关于前沿协议在弱网下的实测对比，详见：[《新一代代理协议解析：Hysteria 2、TUIC v5 与 Shadowsocks-2022 弱网实测》](/2026/10/21/next-gen-proxy-protocols-deep-dive-2026/)。
